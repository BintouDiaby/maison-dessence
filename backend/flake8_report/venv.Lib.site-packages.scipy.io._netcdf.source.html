101

133 Notes

135 This module is derived from
136 `pupynere <https://bitbucket.org/robertodealmeida/pupynere/>`_.
137 The major advantage of this module over other modules is that it doesn't
138 require the code to be linked to the NetCDF libraries. However, for a more

139 recent version of the NetCDF standard and additional features, please consider
140 the permissively-licensed
141 `netcdf4-python <https://unidata.github.io/netcdf4-python/>`_.
142  
143 NetCDF files are a self-describing binary data format. The file contains
144 metadata that describes the dimensions and variables in the file. More
145 details about NetCDF files can be found `here
146 <https://www.unidata.ucar.edu/software/netcdf/guide_toc.html>`__. There
147 are three main sections to a NetCDF data structure:
148  
149 1. Dimensions
150 2. Variables
151 3. Attributes
152  
153 The dimensions section records the name and length of each dimension used
154 by the variables. The variables would then indicate which dimensions it
155 uses and any attributes such as data units, along with containing the data
156 values for the variable. It is good practice to include a
157 variable that is the same name as a dimension to provide the values for
158 that axes. Lastly, the attributes section would contain additional
159 information such as the name of the file creator or the instrument used to
160 collect the data.
161  
162 When writing data to a NetCDF file, there is often the need to indicate the
163 'record dimension'. A record dimension is the unbounded dimension for a
164 variable. For example, a temperature variable may have dimensions of
165 latitude, longitude and time. If one wants to add more temperature data to
166 the NetCDF file as time progresses, then the temperature variable should
167 have the time dimension flagged as the record dimension.
168  
169 In addition, the NetCDF file header contains the position of the data in
170 the file, so access can be done in an efficient manner without loading
171 unnecessary data into memory. It uses the ``mmap`` module to create
172 Numpy arrays mapped to the data on disk, for the same purpose.
173  
174 Note that when `netcdf_file` is used to open a file with mmap=True
175 (default for read-only), arrays returned by it refer to data
176 directly on the disk. The file should not be closed, and cannot be cleanly

177 closed when asked, if such arrays are alive. You may want to copy data arrays
  • E501 Line too long (80 > 79 characters)
178 obtained from mmapped Netcdf file if they are to be processed after the file
179 is closed, see the example below.

181 Examples
182 --------
183 To create a NetCDF file:
184  
185 >>> from scipy.io import netcdf_file
186 >>> import numpy as np
187 >>> f = netcdf_file('simple.nc', 'w')
188 >>> f.history = 'Created for a test'
189 >>> f.createDimension('time', 10)
190 >>> time = f.createVariable('time', 'i', ('time',))
191 >>> time[:] = np.arange(10)
192 >>> time.units = 'days since 2008-01-01'
193 >>> f.close()
194  
195 Note the assignment of ``arange(10)`` to ``time[:]``. Exposing the slice
196 of the time variable allows for the data to be set in the object, rather
197 than letting ``arange(10)`` overwrite the ``time`` variable.
198  
199 To read the NetCDF file we just created:
200  
201 >>> from scipy.io import netcdf_file
202 >>> f = netcdf_file('simple.nc', 'r')
203 >>> print(f.history)

205 >>> time = f.variables['time']

208 >>> print(time.shape)

210 >>> print(time[-1])

223 >>> f.close()
224 >>> data.mean()
