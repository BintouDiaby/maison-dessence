7 .. versionadded:: 0.12.0
8  
9 .. note::
10  
11 The common ``overwrite_<>`` option in many routines, allows the
12 input arrays to be overwritten to avoid extra memory allocation.
13 However this requires the array to satisfy two conditions
14 which are memory order and the data type to match exactly the
15 order and the type expected by the routine.
16  
17 As an example, if you pass a double precision float array to any
18 ``S....`` routine which expects single precision arguments, f2py
19 will create an intermediate array to match the argument types and
20 overwriting will be performed on that intermediate array.
21  
22 Similarly, if a C-contiguous array is passed, f2py will pass a
23 FORTRAN-contiguous array internally. Please make sure that these
24 details are satisfied. More information can be found in the f2py
25 documentation.
26  
27 .. warning::
28  
29 These functions do little to no error checking.
30 It is possible to cause crashes by mis-using them,
31 so prefer using the higher-level routines in `scipy.linalg`.

928 def get_lapack_funcs(names, arrays=(), dtype=None, ilp64=False):
929 """Return available LAPACK function objects from names.
930  
931 Arrays are used to determine the optimal prefix of LAPACK routines.
932  
933 Parameters
934 ----------
935 names : str or sequence of str
936 Name(s) of LAPACK functions without type prefix.
937  
938 arrays : sequence of ndarrays, optional
939 Arrays can be given to determine optimal prefix of LAPACK
940 routines. If not given, double-precision routines will be
941 used, otherwise the most generic type in arrays will be used.
942  
943 dtype : str or dtype, optional
944 Data-type specifier. Not used if `arrays` is non-empty.
945  
946 ilp64 : {True, False, 'preferred'}, optional
947 Whether to return ILP64 routine variant.
948 Choosing 'preferred' returns ILP64 routine if available, and
949 otherwise the 32-bit routine. Default: False
950  
951 Returns
952 -------
953 funcs : list
954 List containing the found function(s).
955  
956 Notes
957 -----
958 This routine automatically chooses between Fortran/C
959 interfaces. Fortran code is used whenever possible for arrays with
960 column major order. In all other cases, C code is preferred.
961  
962 In LAPACK, the naming convention is that all functions start with a
963 type prefix, which depends on the type of the principal
964 matrix. These can be one of {'s', 'd', 'c', 'z'} for the NumPy
965 types {float32, float64, complex64, complex128} respectively, and
966 are stored in attribute ``typecode`` of the returned functions.
967  
968 Examples
969 --------
970 Suppose we would like to use '?lange' routine which computes the selected
971 norm of an array. We pass our array in order to get the correct 'lange'
972 flavor.
973  
974 >>> import numpy as np
975 >>> import scipy.linalg as LA
976 >>> rng = np.random.default_rng()
977  
978 >>> a = rng.random((3,2))
979 >>> x_lange = LA.get_lapack_funcs('lange', (a,))
980 >>> x_lange.typecode
981 'd'
982 >>> x_lange = LA.get_lapack_funcs('lange',(a*1j,))
983 >>> x_lange.typecode
984 'z'
985  
986 Several LAPACK routines work best when its internal WORK array has
987 the optimal size (big enough for fast computation and small enough to
988 avoid waste of memory). This size is determined also by a dedicated query
989 to the function which is often wrapped as a standalone function and
990 commonly denoted as ``###_lwork``. Below is an example for ``?sysv``
991  
992 >>> a = rng.random((1000, 1000))
993 >>> b = rng.random((1000, 1)) * 1j
994 >>> # We pick up zsysv and zsysv_lwork due to b array
995 ... xsysv, xlwork = LA.get_lapack_funcs(('sysv', 'sysv_lwork'), (a, b))
996 >>> opt_lwork, _ = xlwork(a.shape[0]) # returns a complex for 'z' prefix
997 >>> udut, ipiv, x, info = xsysv(a, b, lwork=int(opt_lwork.real))
998

1027 Round floating-point lwork returned by lapack to integer.
1028  
1029 Several LAPACK routines compute optimal values for LWORK, which
1030 they return in a floating-point variable. However, for large
